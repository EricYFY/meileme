# 外卖调度模拟游戏 - 客户端 (Unity) 对接文档 V2.0

这份文档记录了经过架构重构后，Java 后端提供给 Unity 前端的完整接口与数据规范。

## 一、 通信方式与坐标系设定

*   **通信协议**: WebSocket
*   **连接地址**: `ws://localhost:8080/game`
*   **数据格式**: JSON 字符串
*   **逻辑坐标系**: 这是一个 **201 x 201** 的大网格系统，`X` 轴和 `Y` 轴的范围严格限定在 `[-100, 100]` 之间。中心点为 `(0, 0)`。
*   **业务模式**: 前端目前主要作为**数据展示端 (View)**，所有实体（订单、骑手）的创建、移动、状态扭转均由后端计算并主动推送给前端。

---

## 二、 基础数据模型 (Data Models)

在 Unity C# 端，您需要建立以下几个基础的数据类（注意使用支持 JSON 反序列化的库或 `JsonUtility`）：

### 1. 坐标 (Coordinate)
```json
{
  "x": 45.0,
  "y": -32.5
}
```

### 2. 订单 (Order)
```json
{
  "id": "UUID字符串",             
  "pickupLocation": { "x": 12.0, "y": 30.0 },      // 取餐点(商家)坐标
  "deliveryLocation": { "x": -50.0, "y": 80.0 },   // 送餐点(顾客)坐标
  "status": 0,                                     // 订单状态 
  "createTime": 1690000000000                      // 时间戳
}
```
**订单状态字典**:
*   `0`: 待指派 (等待接单)
*   `1`: 已指派 (骑手正在前往取餐)
*   `2`: 配送中 (骑手已取餐，前往送达点)
*   `3`: 已完成 (已送达)

### 3. 骑手 (Rider)
```json
{
  "id": "rider-001",                 // 骑手唯一标识 (共10个)
  "currentPosition": { "x": 0, "y": 0 }, // 实时物理坐标
  "targetPosition": null,            // 当前寻路目标 (空闲时为null)
  "speed": 5.0,                      // 当前移动速度
  "status": 0,                       // 骑手状态
  "currentOrderId": "UUID字符串"      // 关联的订单 (空闲时为null)
}
```
**骑手状态字典**:
*   `0`: 空闲 (原地待命)
*   `1`: 前往取餐中
*   `2`: 前往送餐中 (配送中)

## 三、 WebSocket 服务端下发事件 (Server Push)

WebSocket 连接建立后，Java 端会主动向 Unity 推送事件。所有事件采用统一的“信封”格式：
```json
{
  "type": "事件类型枚举",
  "data": { ... } // 具体的数据体 (Object 或 Array)
}
```

### 1. 产生新订单 `ORDER_CREATED`
*   **触发时机**: 系统每隔约 4 秒定时生成，取餐点根据商家的动态评分（轮盘赌算法）随机决定。
*   **数据体**: `Order` 对象
*   **前端逻辑**: 在 `pickupLocation` 生成一个红色的订单 UI/特效，并在左侧面板添加订单记录。

### 2. 骑手已接单 `RIDER_ASSIGNED`
*   **触发时机**: 系统将某个待指派订单分配给最近的空闲骑手时。
*   **数据体**: 对应的 `Rider` 对象（此时其 status 会变成 1，target 变成取餐点）。
*   **前端逻辑**: 更新对应订单的状态为“已指派”，可选择性地给骑手播放“接到新单”的特效。

### 3. 全局骑手高频同步 `RIDER_UPDATE`
*   **触发时机**: 只要地图上有任何骑手在移动，后端物理引擎就会以 **10Hz (每秒10次)** 的超高频率推送这个事件。
*   **数据体**: **包含 10 个 `Rider` 对象的 JSON 数组 (Array)**。
*   **前端逻辑**: 这是核心渲染事件。Unity 无需在前端计算骑手位移，只需要在每帧 (`Update`) 中，利用接收到的 `currentPosition`，通过 `Vector3.Lerp` 平滑插值更新 3D/2.5D 模型的世界坐标即可。

### 4. 订单送达完成 `ORDER_COMPLETED`
*   **触发时机**: 骑手坐标到达 `deliveryLocation` 且送餐状态结束时。
*   **数据体**: `Order` 对象
*   **前端逻辑**: 播放送达撒花特效，销毁地图上的订单图标，从 UI 列表中移除该订单。

## 四、 补充说明：获取地图数据

目前后端的 Python 引擎会自动生成一份巨大的 `201x201` 的瓦片地图以及商家数据，并在 Java 启动时加载。
**(待开发接口)**：由于目前所有通信强制要求走 WebSocket，如果您（Unity端）需要动态获取地图数据来渲染道路和建筑，请在开发时联系后端（也就是我），我会在 Java 的 `GameWebSocketHandler` 中为您开放一个指令（例如客户端发送 `{"command": "GET_MAP"}`），让 Java 从缓存中读取地图并推送给 Unity。当前您可以先用一块纯色大平板作为背景，跑通上述的骑手移动链路。
